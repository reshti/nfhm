## 1. التفسير الهندسي لسبب خطأ `SIGABRT` و `uv_thread_create` في الاستضافة

عندما قمت بتشغيل أمر `npm install` في استضافة cPanel، واجهت الخطأ التالي:
> `SIGABRT: uv_thread_create failed: Resource temporarily unavailable`

### لماذا حدث هذا الخطأ؟
1. **نظام التحجيم الافتراضي في CloudLinux (LVE - Lightweight Virtual Environment):**  
   في استضافات cPanel المشتركة والسحابية، يضع نظام CloudLinux سقفاً حازماً للموارد لكل حساب عبر قيود صارمة على:
   - الحد الأقصى لعدد العمليات والمسارات المتزامنة (`nproc` / `maxproc`) والتي تُضبط عادة بين 20 إلى 30 Thread فقط.
   - الحد الأقصى لاستهلاك الذاكرة العشوائية (Memory Limit: 1GB).
2. **استدعاء أدوات البناء الثقيلة في بيئة الإنتاج:**  
   المشاريع الحديثة تحتوي في ملف `package.json` على حزم تطوير ضخمة مثل:
   `vite`, `rollup`, `esbuild`, `@tailwindcss/vite`, `typescript`, `tsx`.
   عند تشغيل `npm install` العادي، يقوم مدير الحزم بتفريغ مئات المكتبات وبناء أدوات ثنائية، ويطلق في نفس اللحظة عشرات الـ Worker Threads.
3. بمجرد تجاوز عدد الـ Threads للحد المسموح به في CloudLinux (وهو 20-30)، يفشل نواة لينكس في إنشاء أي خيط معالجة جديد (`uv_thread_create failed`)، فيرسل نظام التشغيل إشارة إجهاض فوري للعملية (`SIGABRT`) ويتوقف الخادم فوراً!
4. **تعارض نوع الوحدة (`"type": "module"` مع Passenger):**  
   مشغل **Phusion Passenger** في cPanel يقوم بتحميل ملف التشغيل الرئيسي عبر دالة `require('./app.js')` في بيئة CommonJS. إذا كان ملف `package.json` يحتوي على `"type": "module"`، فإن Node.js يرفض استدعاء الملف بـ `require` ويظهر خطأ `ERR_REQUIRE_ESM`.

## 2. الحلول الهندسية الجذرية المنفذة في هذه الحزمة

لقد قمنا بحل هذه المشاكل جذرياً خارج الاستضافة وفق أفضل الممارسات العالمية:

1. ✅ **بناء وتوليد الواجهة بالكامل مسبقاً (Pre-built Vite Bundle):**  
   تم تنفيذ أمر `npm run build` في بيئة التطوير، وتوليد كافة ملفات `dist/` المترجمة والمضغوطة بصيغ نسبية (`./assets/...`) تعمل في أي نطاق أو مجلد فرعي (`/` أو `/asd/` أو `/nafham/`).
2. ✅ **حزم خادم إنتاجي مستقل وخفيف (Standalone CommonJS Server):**  
   تم حزم خادم الإنتاج في ملف `server.js` بصيغة CommonJS متوافقة تماماً مع Phusion Passenger، مع تصدير نظيف `module.exports = app`، واستبعاد أي اعتمادية على Vite أو TSX وقت التشغيل.
3. ✅ **ملف `app.js` قياسي لمشغل Passenger:**  
   يعمل كجسر فوري يستدعي `server.js` ويعيد تصدير التطبيق إلى محرك Passenger دون أدنى تعارض.
4. ✅ **تنظيف شامل لملف `package.json` الإنتاجي:**  
   - حذف خيار `"type": "module"` نهائياً لتفادي أخطاء ES Modules مع Passenger.
   - حذف كافة حزم `devDependencies` الثقيلة بنسبة 100%.
   - حصر التبعيات في 3 حزم أساسية فقط خفيفة جداً (`express`, `dotenv`, `@google/genai`).
5. ✅ **تضمين التبعيات الإنتاجية مسبقاً داخل الحزمة (`node_modules` جاهز):**  
   تم تضمين مجلد `node_modules` جاهز ومختبر وخفيف داخل الحزمة، **بحيث لا تحتاج إطلاقاً لتشغيل `npm install` على الاستضافة!**
6. ✅ **خادم ذاتي الاكتفاء:**  
   ملف `server.js` مجمّع ذاتياً ويمكنه العمل حتى بدون `node_modules`، مما يمنحك موثوقية مزدوجة.

## 3. خطوات الرفع والتشغيل بضغطة زر واحدة (1-Click Deployment)

اتبع هذه الخطوات البسيطة للتشغيل الفوري دون الحاجة لفتح Terminal أو تشغيل npm:

### الخطوة 1: إنشاء تطبيق Node.js في cPanel
1. افتح لوحة تحكم **cPanel**.
2. ابحث عن قسم **Software** واضغط على **Setup Node.js App**.
3. اضغط على الزر الأزرق **Create Application**:
   - **Node.js version:** اختر إصدار 18 أو 20 أو 22.
   - **Application mode:** اختر **Production**.
   - **Application root:** اكتب اسم مجلد موقعك (مثال: `nafham` أو `public_html/asd` أو `public_html`).
   - **Application URL:** رابط موقعك أو المجلد الفرعي (مثال: `yourdomain.com` أو `yourdomain.com/asd`).
   - **Application startup file:** اكتب `app.js` (أو `server.js`، كلاهما مدعوم بالكامل).
4. اضغط على **Create**.

### الخطوة 2: رفع الحزمة وفك الضغط
1. افتح **File Manager** (مدير الملفات) في cPanel.
2. ادخل إلى المجلد الذي حددته في **Application root**.
3. ارفع ملف الحزمة: **`nafham_universal_deployment.zip`**
4. اضغط عليه بالزر الأيمن واختر **Extract** (فك الضغط في نفس المجلد).

### الخطوة 3: تشغيل التطبيق (دون الحاجة لتنفيذ NPM Install!)
1. ارجع إلى صفحة **Setup Node.js App** في cPanel.
2. اضغط على زر **Restart** (إعادة التشغيل) فقط!
*(لا داعي للضغط على Run NPM Install لأن كافة التبعيات مجهزة ومدمجة ومختبرة مسبقاً).*

## 4. تجهيز قاعدة البيانات والجداول التسعة

لديك طريقتان سهلتان لتثبيت قاعدة البيانات:

### الطريقة الأولى (الأسهل – عبر معالج التثبيت الذاتي):
1. افتح المتصفح على رابط موقعك متبوعاً بـ `/install`  
   (مثال: `https://yourdomain.com/install` أو `https://yourdomain.com/asd/install`).
2. ستفتح لك شاشة **معالج التثبيت الشامل ذو الـ 5 مراحل**:
   - تأكيد النطاق والمسار المكتشف تلقائياً.
   - إدخال بيانات قاعدة بيانات MySQL التي أنشأتها في cPanel.
   - فحص الاتصال بضغطة زر.
   - زرع الجداول التسعة الشاملة وحساب المدير وتأكيد قفل التثبيت تلقائياً.

### الطريقة الثانية (الاستيراد اليدوي عبر phpMyAdmin):
1. من لوحة cPanel، افتح **MySQL Databases** وأنشئ قاعدة بيانات ومستخدماً واربطهما معاً بكافة الصلاحيات.
2. افتح **phpMyAdmin**، واختر قاعدة البيانات، واضغط على تبويب **Import** (استيراد).
3. اختر الملف المرفق في الحزمة: `database_schema.sql` واضغط **Go**.
   (سيتم إنشاء وزرع الجداول الـ 9 المعتمدة فوراً).

## 6. الجداول التسعة الشاملة المزروعة في النظام
1. `nf_users`: المستخدمون والمشرفون وحسابات الإدارة المشفرة.
2. `nf_certificates`: الشهادات والاعتمادات الرسمية برقم تحقق معتمد (NFH-...).
3. `nf_quiz_questions`: بنك الأسئلة والتقييمات العلمي (105 أسئلة محكمة).
4. `nf_library_topics`: موضوعات مكتبة المعرفة باضطراب طيف التوحد (10 موضوعات).
5. `nf_videos`: استوديو عروض الفيديو والفيلم الوثائقي الرسمي.
6. `nf_team_members`: فريق العمل واللجنة الإشرافية بجامعة الإمام عبدالرحمن بن فيصل.
7. `nf_landing_sections`: ترتيب وتصميم وظهور أقسام المنصة وصفحات الهبوط.
8. `nf_settings`: إعدادات الهوية الوطنية والشعار ورسالة المنصة.
9. `nf_audit_logs`: سجل النشاط والعمليات والتدقيق الأمني.

## 7. آلية التحديث المستقبلي الآمن
عند الرغبة في تحديث المنصة مستقبلاً:
1. ارفع ملفات التحديث فقط إلى مجلد `dist/` وملف `server.js`.
2. لا تقم بحذف مجلدي `data/` أو `uploads/` حتى لا تفقد أي فيديوهات أو إعدادات مسجلة.
3. اضغط **Restart** في cPanel.
